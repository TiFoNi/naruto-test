# NandaGuessr

Угадывай персонажей по признакам и картинкам — без лимитов на день: Наруто, Атака титанов, Блич, Токийский гуль, Берсерк и Dota 2. Неофициальный фанатский проект.

- **По признакам** — вводишь любого персонажа, клетки показывают совпадение: зелёная — совпадает, жёлтая — частично, серая — мимо; ↑/↓ — ответ позже/раньше (или больше/меньше).
- **По картинке** — угадай по сильно увеличенному фрагменту; каждая ошибка немного отдаляет картинку.

Название — в `src/brand.ts`. После входа открывается главная (дашборд): разделы «Аниме» и «Игры», у каждой вселенной свои режимы. Профиль (клик по нику вверху) — ник, статистика по всем играм и режимам, сброс статистики.

Языки интерфейса: RU / UK / EN (`src/i18n`). Тексты интерфейса — `src/i18n/ui.ts`, переводы значений из данных — `src/i18n/values.ts`, имена: EN — оригинальные, UK — автоматически из русских.

Новая вселенная — файл в `src/games/` + запись в `src/games/index.ts`; новый режим — запись в `src/modes.ts` и id в `modes` у вселенной (пока не готов — `UPCOMING_MODES`, показывается как «скоро»).

## Запуск

```bash
npm install
npm run dev
```

## Аккаунты

Играть можно только после входа. Serverless-функции Vercel в `api/`: `auth` (GET — текущий профиль, POST `action: login | register | logout`), `profile` (`action: nickname | reset`), `duel` (`action: create | join | setup | ready | state | guess | giveup | next | lobby`), `challenge` (`action: create | view`), `round/*` (`current`, `guess`, `giveup`, `image`), `leaderboard` (`daily=1` — ежедневные). Файлы в `api/_lib/` функциями не становятся — подчёркивание в начале это и означает. На плане Hobby у Vercel максимум 12 функций — сейчас их 9, новые эндпоинты добавляются параметром `action` в существующие, а не новым файлом.

Раунды считает сервер: он загадывает персонажа, проверяет каждую попытку и отдаёт только цвета клеток (правила сравнения — `src/games/specs.ts`, общие для клиента и сервера), картинку в режиме «По картинке» отдаёт `api/round/image`, так что ответ не виден в браузере до конца раунда. Каждый раунд хранится в коллекции `rounds` (кто, игра, режим, загаданный, все попытки, итог, время); незаконченный раунд продолжается после перезагрузки. Статистика и таблица лидеров (отдельно для каждой вселенной и режима) строятся только из серверных результатов. Данные персонажей попадают в функции через `includeFiles` в `vercel.json`. Пользователи, ники и статистика хранятся в MongoDB (коллекция `users`, пароли — scrypt), сессия — JWT в HttpOnly-cookie на 30 дней. Ошибки API — коды (`taken`, `bad_credentials`…), текст подставляет клиент на нужном языке.

Нужны переменные окружения (в Vercel → Settings → Environment Variables, локально — в `.env.local`, пример в `.env.example`):

- `MONGODB_URI` — строка подключения MongoDB Atlas;
- `AUTH_SECRET` — случайная строка минимум из 32 символов;
- `MONGODB_DB` — имя базы (необязательно, по умолчанию `nandaguessr`).

`npm run dev` поднимает эти функции и локально (плагин в `vite.config.ts`).

**Манга** (`scripts/build-manga.mjs`) — режим «по странице»: страница из манги и три варианта ответа. 50 тайтлов зашито в `TITLES` (45 с готовыми страницами — только они попадают в пул) внутри скрипта (id на MangaDex — в `MANGADEX_IDS`, там же обходы для тех, кого поиск находит неправильно), у каждого ровно по 3 страницы. Обложка 1-го тома качается автоматически и кладётся рядом как `cover.jpg`, в пул страниц не попадает. Страницы кладутся в `seeds/manga/<slug>/` (в git не попадают, см. `seeds/manga/README.md`) и скриптом сжимаются в `public/manga/pages/<id>/N.webp`. Файл `cover.*` становится обложкой. Номер страницы и три варианта ответа лежат в `rounds.extra` как `<страница>|<id>,<id>,<id>` — поэтому ежедневный режим и дуэли работают без изменений схемы. Тайтлы без картинок в пул не попадают, а игра целиком скрывается с дашборда, пока пул пустой.

**Соул Итер** (`scripts/build-se.mjs`) — Soul Eater Wiki: состав собирается из объединения категорий (сама `Character` неполная — там нет Кроны и Арахны), пол/вид/роль/организация/сторона/статус из категорий, арка дебюта по главе; инфобоксы там бывают в одну строку, поэтому поля читает собственный парсер со счётом скобок; NOT!, GAIDEN и неканон отбрасываются; пул — топ-50 по длине статьи.

**Пламенная бригада** (`scripts/build-ff.mjs`) — Fire Force Wiki: данные лежат на отдельных страницах `Infobox:<имя>`, поколение из поля `type`, номер главы дебюта достаётся резолвом редиректов плюс карты названий глав из страниц арок; двойники (doppelgänger) отбрасываются; пул — топ-55 по длине статьи.

**ДжоДжо** (`scripts/build-jojo.mjs`) — JoJo's Bizarre Encyclopedia: части 1–7 собираются из двух систем категорий (`Stardust Crusaders Characters` и `Part 3 Characters`), пол и национальность из инфобокса, вид/сила/группы/сторона — из категорий, альтернативные версии страниц пропускаются; пул — топ-70 по длине статьи.

**Чёрный клевер** (`scripts/build-bc.mjs`) — Black Clover Wiki: пол, раса, магия (атрибут сводится к списку правил, иначе «другая магия»), орден, королевство, статус, арка дебюта; картинки — «<имя> anime profile.png», иначе кадр из манги; пул — топ-60 по длине статьи.

Третьестепенные персонажи отсекаются при сборке: в каждой вселенной остаются только самые известные (константа `KEEP` в скрипте — Наруто 250, Атака 100, Блич 160, Гуль 100, Берсерк 85; безымянные вроде «отец X» / «Mr. X» — всегда), их картинки удаляются из `public`.

После пересборки данных запускай `npm run check:data` — проверяет логические противоречия между колонками (например, «титан-оборотень» без силы титана, банкай без расы шинигами, кагуне у человека). Правила — в `scripts/check-data.mjs`, исправления делаются в скриптах сборки (функции `consistent`).

Общие хелперы для вики и картинок — `scripts/lib.mjs`.

Миниатюры собираются в один атлас (`thumbs.webp`), чтобы грузились одним запросом. Кэш запросов — в `.cache/` (не в git).

## Удалённые персонажи

Вики тащат и статистов — школьников на фоне, безымянных шиноби, персонажей в масках, которых по картинке не угадать. Список удалённых лежит в [`scripts/dropped.mjs`](scripts/dropped.mjs) как `DROPPED` — id по играм; каждый билд-скрипт вызывает `dropDeleted(result, '<игра>')` перед записью, так что персонаж исчезает и из json, и из атласа, а его картинку удаляет `pruneImages`. Пережить `npm run data` иначе нельзя — вручную вычищенный json перезатрётся.

Важно: в базе остаются раунды, дневные загадки и вызовы со старыми id. Поэтому сервер лечит их сам — активный раунд с неизвестным персонажем удаляется и выдаётся новый (`playable` в `api/_lib/rounds.ts`), документ в `dailies` пересобирается на актуальном пуле (`dailyAnswer`), попытки с удалёнными id отфильтровываются в `roundView` и `duelView`, а вызов на удалённого персонажа отдаёт 404. Без этого после выкатки новых данных игра падала с «Ошибка сервера» у всех, кто держал незаконченный раунд.

Удалять стоит только тех, кого реально никто не вспомнит: у второстепенных вроде Бавабавы или Ганджу на MyAnimeList фанатов больше, чем кажется (`.cache/mal-<id>.json`, Jikan `/anime/<id>/characters` — там же поле `favorites`).

## Ежедневные

Для каждой игры и режима раз в день (00:00 по Киеву) загадывается один персонаж для всех — `api/_lib/daily.ts`. Порядок — перестановка пула по HMAC от `DAILY_SECRET` (или `AUTH_SECRET`), без повторов до конца цикла; ответ дня фиксируется в коллекции `dailies`. У игрока один ежедневный раунд в день (`rounds.daily = YYYY-MM-DD`, уникальный индекс), статистика — в `stats.<game>_<mode>_daily` с серией дней подряд. Лидеры дня и серии — `api/leaderboard?daily=1` (`api/_lib/daily-board.ts`), маршруты `#/play/:game/:mode/daily` и `#/leaderboard/:game/:mode/daily`.

## Режимы по играм

Набор режимов у каждой игры свой: `modes` в `src/games/specs.ts` (по умолчанию `classic` + `image`) и в `src/games/<game>.ts`. Статистика, лидерборды, ежедневные и вкладки строятся по этому списку.

**Dota 2 — «По способности»** (`scripts/build-dota-abilities.mjs`): иконки способностей из CDN Valve, названия на ru/uk/en из `dota2.com/datafeed/herodata`; врождённые, аганимовые и шардовые способности пропускаются. Для каждой иконки заранее готовятся 5 стадий размытия/обесцвечивания (`public/dota/abilities/s0..s4`), сервер отдаёт стадию по числу ошибок (`api/round/image`), так что открыть картинку в новой вкладке ничего не даёт. Название способности открывается после 7 ошибок. Какая способность загадана — хранится в `rounds.extra` (в ежедневном — в `dailies.extra`, одна на всех).

## Дуэли

Комната на двоих живёт между раундами: `#/duels` (создать / зайти по коду / история) и `#/duel/:code`. Всё через один эндпоинт `api/duel.ts` (`action`: create, join, setup, ready, state, guess, giveup, next, lobby), логика — `api/_lib/duels.ts`, коллекция `duels`.

Поток: создаётся пустая комната (по умолчанию Наруто + по признакам), хозяин меняет игру и режим (`setup` сбрасывает готовность), оба жмут «Готов» → раунд. 10 минут на раунд (без «минуты добивания»). Победитель: угадал > меньше попыток > быстрее, иначе ничья. После раунда: «Ещё раунд» (нужны оба) стартует следующий раунд в той же комнате, «В комнату» возвращает в лобби обоих. В комнате ведётся счёт серии (`players[].wins`, `draws`), общий счёт — в `users.duelStats`, истории дуэлей нет: счёт серии живёт только внутри комнаты и исчезает вместе с ней, в профиле — только «Побед в дуэлях» (`users.duelStats`, сбрасывается вместе со статистикой). Спам-защита 0.8 с, соперник видит только число попыток, картинки — `api/round/image?duel=<code>`, клиент опрашивает состояние раз в 2 секунды (только когда вкладка активна), комната удаляется только после 7 дней без единого захода (TTL по `touchedAt`, который обновляется при каждом обращении).

## Загадать другу

Кнопка «Загадать другу» стоит в шапке игры рядом с «Лидерами» (только в бесконечных режимах) и открывает модалку `ChallengeMaker` — в поток раунда она не лезет. Выбираешь персонажа — получаешь ссылку `#/c/<код>` (7 символов из алфавита без похожих букв). Друг открывает её и угадывает именно этого персонажа в том же режиме.

Эндпоинт `api/challenge.ts` (`action: create | view`), логика — `api/_lib/challenges.ts`, коллекция `challenges` (TTL 60 дней). Раунд создаётся через `challengeRound` и хранит код в `rounds.challenge`; уникальный индекс `{userId, challenge}` не даёт переигрывать — при повторном заходе возвращается тот же раунд. Результат в статистику по играм и в лидерборд не идёт (`finishRound` для таких раундов возвращает `stats: null`), вместо этого попытки записываются в `challenges.solves` — и удачные, и сдачи (`solved: false`, пишет `skipRound`). В профиле копится только счётчик `users.challengeStats.solved` — «Отгадано загадок», растёт лишь на выигрыше и сбрасывается вместе с остальной статистикой. Страница одна и та же для автора и для того, кто уже отгадал (меняются только подписи): загаданный персонаж, все попытки каждого игрока чипами и ссылка для повторной отправки. Ники прогоняются через `defaultNickname`, иначе в списке светится почта. Кто ещё не закончил раунд, `answerId` не получает — ему отдаётся сам режим.
