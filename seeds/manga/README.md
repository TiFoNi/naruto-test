# Картинки для режиму «За сторінкою»

Кидай сторінки в папку свого тайтла, наприклад `seeds/manga/berserk/`.

У `scripts/build-manga.mjs` кожен тайтл має власний id першим числом у рядку —
він і є id у базі. Додаєш новий тайтл — дай йому наступний вільний номер, а не
переписуй чужі, інакше активні раунди почнуть показувати не ту мангу.

- Формат будь-який: `.jpg`, `.png`, `.webp`
- Назви по порядку: `1.jpg`, `2.jpg`, `3.jpg` — так вони й підуть
- **Обкладинка підтягується сама** — при першому запуску скрипт качає справжню
  обкладинку 1-го тому з MangaDex і кладе її поруч зі сторінками як `cover.jpg`.
  Тобто вона видима, її можна подивитись і замінити на свою
- `cover.jpg` показується на екрані результату й у мініатюрах, але **ніколи не
  трапляється серед сторінок для вгадування**
- Не сподобалась автоматична — просто перезапиши `cover.jpg` своєю. Видалиш —
  скрипт скачає знову

Скільки класти: від 3–5 сторінок на тайтл, інакше вони швидко почнуть
повторюватись. Тайтли без картинок у грі не з'являються взагалі.

Обирай сторінки, де **не видно назву манги й імена персонажів**, інакше
вгадувати нема чого. Найкраще працюють розвороти з екшеном або пейзажем —
там видно стиль.

Після того як закинув файли:

    npm run data:manga

Скрипт стисне все у webp, збере атлас і перерахує `src/data/manga.json`.
Оригінали з `seeds/` у гру не потрапляють і в деплой не їдуть.

## Автоматичний набір сторінок

    npm run data:manga -- --pages

Для кожного тайтла скрипт знаходить його на MangaDex, бере **три розділи з
різних місць** (15%, 50% і 85% від усієї манґи) і з кожного — сторінку з
середини. Так три картинки ніколи не з одної сцени. Що вже завантажив, записує
в `.cache/manga/pages.json` і вдруге не чіпає — щоб перезібрати все наново,
додай `--force`.

Мови пробуються по черзі: en, ru, uk, es-la, pt-br — береться перша, де є хоча б
три розділи. Ліцензовані тайтли з MangaDex видалені, тож для частини манґи
сторінок там немає взагалі — їх і далі треба класти руками.
